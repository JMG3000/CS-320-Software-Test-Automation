# CS-230 Software Testing & QA Automation

Testing gives a developer the ability to ensure stability. By testing as code is written, code can correctly align with the requirement needed. This produces software that does what it is needed to do and in a consistent manner. Testing can validate logic under normal use, as well as edge cases to provide secure, stable, and functional software.  

Tests can only be successful if the requirements are gathered correctly from the user. The user needs should be verified before any code is written, but that is not always possible. I believe that alignment meetings could be useful for this situation to realign the current software. 

I approach building software by gathering requirements first as they are used to design and build the software. For the requirements, I listen to the user to understand what they need. I can then ask well-formed questions to gather specific information as needed. The more information regarding the user’s needs for the software, the better the requirements can be understood. 

I can then extract constraints from that information to not only correctly build the software but to also provide test cases. This is important to verify that the functionality correctly reflects the originally gathered requirements. This reflects the importance of gathering user requirements before building a system.
